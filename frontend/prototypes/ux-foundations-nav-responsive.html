Protótipo — UI foundations, navegação e responsivo

Análise visual do EXEQ Hub (SPA + cadastros). Use os controles de viewport para comparar desktop, tablet e phone. Não altera o app em produção — só protótipo de design.

Problema atual Abaixo de 980px a sidebar some sem substituto: o usuário perde o menu. Cadastros abrem em outra interface (Django), quebrando continuidade. Jobs fiscais (emitir, cobrar, DAS) não têm prioridade visual sobre config.
Proposta neste protótipo IA reagrupada (Início / Fiscal / Financeiro / Cadastros / Conta). Phone: bottom bar com 4 destinos + drawer “Mais”. Lista NFS-e vira cards no phone. CTA “Emitir NFS-e” sempre no topo.

Como usar este protótipo com o time

  1. Validar a IA de navegação (nomes de grupos e prioridade NFS-e / Cobrar / DAS).
  2. Validar o phone shell: bottom bar + drawer é suficiente para o dia a dia do prestador?
  3. Decidir se cadastros entram no SPA antes ou depois do drawer unificado.
  4. Quando aprovado, implementar no HTML/CSS do Hub (F0–F3 da análise em Docs/Exeq_Hub_UX_Analise_Navegacao_Responsive.md).
